# EcoEnchants 2026.27-1 性能优化与交接

日期：2026-10-23，按用户 Asia/Tokyo 会话日期记录。未部署生产服。

复杂混合附魔武器在本地同条件测试中，一次显示加一次恢复的临时分配从 178428 B 降至 146328 B，合计减少 **17.99%**。这不是整个插件或全服 CPU/内存下降比例。

## 生产 JAR 与 mcfx 是否一致

- 以作者指定的 `33444dirge/EcoEnchants` / `mcfx` 为准，固定提交 `84e4e1fd6d0760530eed521cbf3e1bc27b5cb18e`，远端核对时仍为该提交。
- 用户下载目录、桌面 eco系列、交接包中的 EcoEnchants 均为同一 SHA256：`f7a626d81ba24005d077bdf4a23ffdd70eb5e560aa73dfa984809737cb22d2e6`，1106864 B。
- mcfx 基线构建与生产 JAR：178 个项目类中 175 个逐字节相同，余下 3 个的反汇编指令、字段和方法签名一致。`javap -v` 差异为 libreforge 内联源码的 SMAP 调试行号（169/245 与 156/223），不是业务指令差异。完整差异保存在证据包 `baseline-debug-diff.txt`。
- 11/11 内置资源与 mcfx 相符：只归一化 CRLF/LF 和明确版本/插件名占位符。正式优化版保留这些资源语义，仅插件版本变为 `2026.27-1`。
- 不能仅因官方另一条主线为 2026.42 就判断生产版旧于 mcfx；此前这两种“最新版”的表述已纠正。本次没有迁移官方主线。
- 原始基线首次 `check` 因 Windows 中文路径测试 worker 问题失败；其中成功生成的基线 shadow JAR 仅用于源码指纹核对，不作为交付成品。最终交付经过独立干净构建及完整测试。

## 改动与功能边界

1. `EnchantmentTargets.kt`：删除可附魔/容量查询前的完整物品哈希。根据已验证 eco 匹配器的必要材质建立候选索引，**候选仍执行原 matches()**；`ModifiedTestableItem` 的附加条件、`MaterialTestableItem` 的自定义物品排除条件均保留。未知匹配器、子类和外部目标进入原规则回退。
2. 索引以 eco 已发布的不可变 registry values 集合引用为版本；注册、删除及同 ID 替换都会让后续查询重建。只保留一份当前索引，按材质/规则计规模，不按玩家、物品或数据包增长。构造完成后通过 volatile 发布，没有新增锁、线程或调度任务。
3. `EnchantDisplay.kt`：先判断 require-enchantable 开关，关闭时省掉无用匹配；没有关闭描述、折叠、条件提示或容量提示。
4. `EnchantFinder.kt`：原来的 FastItemStack.getEnchants() 是 `checkStored=false`，改为原生 ItemStack.getEnchantments()，保留只激活直接附魔、忽略存储附魔的既有行为。槽位检查改为直接 any，不构造中间列表。
5. 本次没有修改附魔效果、概率、数值、命令、权限、GUI 输入归还、持久化结构或默认配置。applicableEnchantments 的原缓存未改。

原来可附魔/容量查询有五秒缓存；现在仍按实际谓词检查，自定义外部状态或目标替换可以更快反映到这些查询。这不是放宽匹配条件。

## 实测收益

| 场景 | 旧版 B/次 | 优化版 B/次 | 临时分配减少 | 本机耗时减少 |
|---|---:|---:|---:|---:|
| 复杂混合附魔武器：显示 | 160776 | 141440 | 12.03% | 13.66% |
| 复杂混合附魔武器：恢复 | 17652 | 4888 | 72.31% | 64.20% |
| 复杂混合附魔武器：识别 | 1984 | 656 | 66.94% | 48.75% |
| 复杂但无附魔武器：显示 | 138216 | 128752 | 6.85% | 17.89% |
| 复杂但无附魔武器：识别 | 1528 | 24 | 98.43% | 96.31% |
| 普通无附魔武器：显示 | 9524 | 9384 | 1.47% | 18.61% |
| 普通无附魔武器：恢复 | 2828 | 2528 | 10.61% | 31.11% |
| 复杂不可附魔物品：显示入口 | 10456 | 568 | 94.57% | 96.00% |


固定复杂物品为 24 行 Lore、16 个无关 PDC 字符串及模型数据；混合物品另外包含 2 个原版附魔、3 个真实注册的自定义附魔。另测附魔书、普通物品、不可附魔物品、普通 Bukkit ItemStack 与原生 CraftItemStack。

B/次来自有效的平台线程 ThreadMXBean 分配计数，不是虚拟区域线程的 -1 读数，不是常驻内存或泄漏量。显示/恢复包含每次克隆物品的成本；显示性能测量的 player 为 null，不包含有玩家时的条件 holder 计算。玩家相关显示只做功能对照，没有冒充其性能收益。

最终性能数据仅取 run11、run12，两次独立 JVM 启动。每场景每版本 8 轮预热、12 轮测量，旧/新顺序交替；每轮显示 500 次，其余操作各 2000 次。每版共 1224000 次有效测量调用，两版合计 2448000 次。表中用 24 个批次均值的中位数，耗时是本机墙钟时间，受 JIT/GC/系统波动影响。

附魔书容量查询走的仍是原有相同代码，424 -> 424 B/次，分配没有优化；此次计时反而慢 5.40%，应视为无确定提速而非宣称全场景必定更快。所有 30 个场景及每批原始数据见 `results.json`。

历史 Spark 的 39.24/12.98 MiB/s 是不同人数、核心和负载下的来源子树，不可乘上本表百分比推算当前服收益。本次没有测量整服 CPU、MSPT、总堆占用、网络带宽或数百玩家并发能力。

## 对玩家和管理员的影响

玩家：已测试的附魔显示、描述/折叠、容量、隐藏状态、识别、等级和槽位结果一致；不需要换装备或重新附魔。目标是减少物品显示与装备识别的重复工作、降低临时对象分配造成的 GC 压力；不能承诺每台服务器或所有玩法固定提高 TPS。未删效果、调低频率或关闭功能换取跑分。

管理员：本次只替换 EcoEnchants；无需修改 YAML、权限或数据库，也不要求同步升级官方主线依赖。正常停服后备份旧 JAR，只保留一个 EcoEnchants 加载副本，再放入 `EcoEnchants-2026.27-1.jar` 启动。回滚时正常停服换回原 JAR；本次没有配置/数据迁移需要倒退。未操作生产服务器。

上线收益需要在相同核心/依赖/配置、相近人数与动作下重新采样 Spark。源码保留在 fork 的 `mcfx` 基线上；`mcfx` 分支本身保留原作者提交，优化在 `codex/performance-20261023`。
