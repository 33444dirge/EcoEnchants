# EcoEnchants GUI 物品处理修复报告

日期：2026-10-06；断线丢物补充：2026-10-07

## 修复前的问题

玩家反馈在 `/ecoenchants gui` →「附魔大全」中，偶尔可以把关闭按钮等展示物品拿进背包。展示物品不是玩家物品，不应被取出。

1. **菜单登记表并发访问不安全。** eco 用普通 `WeakHashMap<Inventory, RenderedInventory>` 保存正在显示的菜单，并用普通 `MutableMap` 暂存正在切换的菜单。Folia 上不同玩家的事件可能在不同区域线程同时访问这些映射。登记查找不到菜单时，点击处理会在取消交易前直接返回。这是能够解释偶发取出的代码路径；缺少当时的玩家操作日志，不能断定某次取出的唯一原因。
2. **点击事件内直接切换窗口。** 关闭、列表条目和返回按钮原先在 `InventoryClickEvent` 尚未结束时关闭或打开窗口，使背包交易与窗口切换交错。
3. **延迟刷新未绑定玩家线程和窗口实例。** Folia 上的刷新任务可能在错误线程执行；只比较菜单对象时，旧窗口的任务也可能刷新同一菜单对象创建的新窗口。
4. **旧版附魔 GUI 归还路径重复。** 返回分组手动归还一次，关闭回调又归还一次；关闭回调读取玩家当前菜单时，还可能读到新窗口的空输入槽。
5. **断线时真实输入物品可能丢失。** 关闭回调原先将输入槽物品交给 eco 的 `DropQueue`。默认快速合并队列在后续 tick 才归还；指定核心在触发关闭回调后、队列执行前保存玩家数据。队列随后将物品加入已经离线的旧 `Player` 实例，重连读取的存档里没有这件物品。该缺陷在旧版菜单、物品查询和铁砧模拟器中复现；没有证据表明它是上述展示物品修复新引入的。

## 修复后的代码行为

- eco 的菜单登记表改为同步映射，切换窗口的暂存映射改为 `ConcurrentHashMap`；点击和拖拽不会因为跨区域并发读写登记表而漏掉菜单。
- eco 的延迟刷新在玩家所属线程执行，刷新前核对具体窗口实例；旧窗口的任务不再刷新新窗口。
- EcoEnchants 的关闭、返回和跳转先取消点击交易，再于玩家线程的下一 tick 执行；执行前确认玩家仍打开触发点击的窗口。
- 旧版附魔 GUI 只在关闭回调中，从正在关闭的窗口取出待归还物品，避免返回分组时重复归还。
- 新增共用的 `returnCaptives`：旧版附魔 GUI、物品查询、铁砧模拟器和附魔详情的关闭回调从**正在关闭的窗口**读取真实输入物品，先清空输入槽，再**在该回调内**放入玩家背包。满背包时，仅将未放入的物品立即落在玩家所在位置；不再等待下一个 tick 的 `DropQueue`。清空输入槽使重复关闭回调不会重复归还。落地点使用玩家实际位置，避免 Folia 区域边界处将掉落物生成到相邻区域。

## 旧 JAR 的真实服务端验证

`D:\Downloads\runtime-review.txt` 记录了 2026-10-07 的隔离服测试。被测 EcoEnchants JAR 的 SHA-256 是 `79626711451BF752A4D9F432510C7E1D31C00C85F003A0762E1B981D7CF2611A`：它包含展示物品防取出修复，**尚未包含本报告的同步归还修复**。核心为 shiroha 26.2 DEV，eco 为 2026.28，eco 配置使用默认的 `use-fast-collated-drops: true`。

测试使用两个真实 TCP 客户端发送容器点击和拖拽包，探针只观察事件与服务端库存。两个玩家分别位于不同 Folia 区域。正式套件和诊断补测共 62 次服务端库存/光标断言：56 次通过，6 次失败；观察到 330 次 `InventoryClickEvent` 和 4 次 `InventoryDragEvent`。

- **展示物品防取出：通过。** 关闭按钮的左/右键、Shift 点击、数字键、副手、Q、Ctrl+Q、创造模式中键、底部背包双击收集、Shift 转移、触及顶部的拖拽，以及列表导航、连续操作和旧窗口延迟刷新，均未使展示物品进入玩家背包。
- **正常关窗归还：通过。** 旧版菜单、当前物品查询和铁砧模拟器的真实输入物品正常归还。
- **断线归还：失败。** 6 次失败均复现同一个缺陷：输入槽放入一把唯一命名的钻石剑后保持窗口打开并断线，重连后的剑数量从期望的 1 变成 0。探针观察到 `DropQueuePushEvent` 发生时玩家已离线；旧窗口的归还晚于退出保存。附近没有掉落物，合并队列也已清空。

上述数据证明旧 JAR 的展示物品保护在该环境生效，同时证明旧归还路径存在断线丢物；不能将这 6 次失败解释成 6 个不同缺陷。测试报告中的隔离目录 `D:\codex-gui-validation-20261007` 在当前工作环境不存在，无法直接复用它的客户端套件和证据目录。
